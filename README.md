## 项目简介

本博客聚焦于移动端（iOS / Android / WebView）性能的采集与分析：

- 介绍关键性能指标及其含义
- 展示如何设计采集方案和埋点策略
- 说明上报、存储与预处理的常见做法
- 给出系统化的分析流程与实战案例
- 演示如何使用大模型/AI 工具辅助定位与总结性能问题

## 为什么关注移动端性能

移动端的性能直接影响用户体验与业务指标（留存、转化等）。移动网络波动、设备性能差异、App 与 WebView 的渲染差异都会导致复杂的问题，需要通过系统化的数据采集与分析来定位与优化。

## 性能采集的基本原理

### 常用指标

- 启动时延（Cold/Hot Start）
- 首屏时间 / 白屏时间
- 页面/界面交互耗时（响应时间、FPS、主线程阻塞）
- 网络相关（请求时延、失败率、重试）
- 内存 / CPU / 电量消耗
- 卡顿（jank）与掉帧

### 采集方案与埋点实践

- SDK 层面采集（埋点/自动埋点）
- 使用系统 API（如 Android Trace、iOS Instruments）
- 前端性能 API（PerformanceTiming / PerformanceObserver）
- 采样策略与上报频率（全量 vs 采样）

### 上报与存储

- 批量上报与实时上报的权衡
- 数据清洗（去重、错误数据过滤）
- 指标聚合（按时间窗口、按版本、按机型）

## 性能分析思路

- 从宏观指标入手定位影响面（版本、地域、网络类型、机型）
- 使用分布与聚合视图发现异常区间
- 按 session/trace 回溯问题发生的上下文
- 对比回归分析：版本间、配置间的对比

## 使用 AI 辅助���析

### AI 可以做什么

- 自动生成性能问题的摘要与可能原因
- 将长日志或 trace 数据摘要为关键事件
- 根据指标与上下文输出初步诊断思路与排查步骤
- 生成可执行的检测规则或告警条件

### 常见工作流

1. 数据准备：将聚合后的关键指标、异常样本与上下文（设备、系统、版本、网络）作为输入。  
2. Prompt 设计：构造包含问题描述与数据的清晰 Prompt（见示例）。  
3. 分析与验证：AI 输出假设后结合实测或更多日志验证。  
4. 自动化：把常用诊断 Prompt 封装进脚本或工具链中，提升排查效率。

### 示例 Prompt（中文）

示例 1 — 概览与可能原因：

"我有一批用户指标，包含：版本号、机型、网络类型、平均首屏时间、75分位首屏时间、错误率。请帮我总结可能的性能问题并按优先级排序，指出需要进一步查看的日志与检测步骤。"

示例 2 — trace 摘要：

"以下是一次慢启动的 trace（按事件时间顺序）：[在此粘贴事件列表或关键调用栈]。请提取 3 个最可能的性能瓶颈并给出对应的优化建议。"

示例 3 — 告警规则生成：

"我想要一个告警规则，用于检测首屏时间回归：当某版本的 P75 首屏时间较上一版本上升超过 30% 且样本量 > 100 时触发。请给出伪实现代码或 SQL 示例。"
